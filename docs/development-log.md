# 开发日志

## 2026-06-10

### 项目目标

构建一套面向购销合同的智能法务审查 Web 应用，覆盖合同输入、审查策略配置、智能审查调用、结构化风险展示、报告复制与下载等核心流程。

### 已完成能力

- 搭建 Next.js + TypeScript 前后端一体项目。
- 完成首页、审查工作台、结果报告页三大核心页面。
- 实现 `/api/review` 服务端接口，封装智能审查工作流调用。
- 实现 `/api/review-file` 文件版审查接口，支持先上传合同文件到 Coze 并通过 `file_id` 执行工作流。
- 实现 `/api/health` 健康检查接口，用于展示当前系统连接状态。
- 实现结果标准化逻辑，兼容结构化 JSON、字符串化 JSON、Markdown 和纯文本返回。
- 增加示例审查结果兜底，保证在外部工作流未配置时仍可完成完整产品体验。
- 支持合同文本粘贴和 `.txt` / `.docx` 文件上传解析。
- 支持审查立场选择：买方 / 卖方。
- 支持审查模式选择：快速审查 / 精细审查。
- 结果页支持风险评分、关键风险发现、风险等级筛选、风险清单、报告正文。
- 结果页支持复制报告、下载 `.md` 报告、下载 `.txt` 报告。
- 生成正式报告元数据：报告编号、生成时间、报告来源、审查范围、审查配置。

### 页面设计推进

- 首页从功能入口升级为产品官网式高保真页面，重点表达客户痛点、产品优势和审查流程。
- 审查页从基础表单升级为业务工作台，包含合同材料、审查策略、系统连接、审查覆盖范围和输出内容。
- 结果页从普通表格升级为专业报告页，包含报告 Hero、风险评分、报告详情、关键风险卡片和可筛选风险清单。

### 技术结构

- `app/page.tsx`：产品首页。
- `app/review/page.tsx`：合同审查工作台。
- `app/result/page.tsx`：智能审查报告页。
- `app/api/review/route.ts`：审查接口。
- `app/api/review-file/route.ts`：文件版审查接口。
- `app/api/health/route.ts`：健康检查接口。
- `lib/coze.ts`：智能审查工作流 API 封装。
- `lib/normalizeResult.ts`：审查结果标准化。
- `lib/mockResult.ts`：示例审查结果。
- `lib/types.ts`：类型定义。

### 当前限制

- 当前文件解析支持粘贴文本、`.txt` 和 `.docx`。
- 复杂 PDF、扫描件 OCR 可作为后续增强。
- 真实智能审查效果取决于外部工作流的提示词、输入协议和输出结构稳定性。
